Project specification

codex-switch v2：Codex 专用本地模型路由器

当前项目聚焦 codex-switch。产品目标是让用户先显式配置 OpenAI-compatible 供应商，再启用本地代理。Codex 始终固定使用 codex-switch provider，真实上游在本地代理内切换。

显式供应商 新安装状态下不内置默认上游。
先添加再启用 没有 active provider 时提示先添加。
登录态保护 不修改 Codex 的 auth.json。
关闭前恢复 退出应用前恢复 Codex 配置。

技术栈

桌面壳

Tauri 2，关闭系统标题栏，使用自绘标题栏和窗口控制按钮。

tauri decorations=false data-tauri-drag-region

后端

Rust 负责配置写入、透明代理、系统凭据、更新检查和退出恢复。

Rust Axum Reqwest Tokio

前端

React + TypeScript + Vite。UI 使用 CSS token 支持浅色、暗黑和系统主题。

React TypeScript Vite lucide-react
状态存储 P0 使用 ~/.codex-switch/state/state.json。provider 历史、用量统计进入 P1 后再迁移 SQLite。
配置编辑 使用 toml_edit，避免字符串替换误伤 [mcp_servers.*] 和 [projects.*]。
系统凭据 第三方 API Key 使用系统 keyring。状态文件只保存引用，不保存明文。
软件更新 使用 Tauri updater plugin，发布包必须签名，支持静态 JSON 或动态更新服务。

项目结构最佳实践

结构按“产品层、桌面桥、系统能力、代理能力”分离。前端只处理交互和展示；Rust 后端承载所有会影响用户系统状态的动作。

功能范围

v1 基础能力

  • Provider 添加、编辑、删除和设为当前。
  • 支持第三方 OpenAI-compatible Endpoint。
  • 支持 codexswitch:// 和 ccswitch:// 导入。
  • 启动本地代理，写入 Codex 配置。
  • 停用时恢复 Codex 配置，不修改登录态。
  • 基础日志、健康检查和端口设置。

v2 必须修正

  • 首次启动不再注入默认官方 provider。
  • 没有 active provider 时首页主按钮显示“先添加”。
  • 添加带 API Key 的 provider 后才能启用。
  • 无效 active provider 会被归一化为空。
  • 转发必须剥离 Codex 登录凭据。

具体实现功能

首页状态 展示未启用、已启用、代理端口、Codex 配置目录、登录态诊断、当前目标、最近请求。未选择供应商时主按钮为“先添加”。
启用接管 启动本地代理，备份 config.toml，写入固定 model_provider = "codex-switch"，并禁用 WebSocket。
停用恢复 停止代理，恢复启用前的 model_provider、model、openai_base_url，清理旧 codex-switch provider。
Provider 管理 用户 provider 支持添加、编辑、删除、保存草稿、设为当前和拉取模型列表；缺少 API Key 时不能设为当前。
链接导入 解析 codexswitch:// 和 ccswitch://，展示预览，遮罩 API Key，确认后保存。
透明代理 支持 /health、/v1/models、/v1/responses、/v1/responses/compact，流式响应原样返回。
主题系统 浅色、暗黑、跟随系统三种模式，设置持久化，自绘窗口栏和所有状态组件同步换肤。
更新系统 设置页提供检查更新、下载更新、安装更新；安装前统一调用恢复保护，避免 Codex 指向已停止代理。
窗口系统 无系统标题栏，自绘拖拽区域和最小化、最大化、关闭按钮；关闭请求被拦截并先恢复 Codex 配置。

新增能力

暗黑模式切换

提供浅色、暗黑、跟随系统三种策略。主题以 CSS variables 实现，并持久化到本地状态。

  • 前端使用 data-theme 切换 token。
  • 设置页提供主题选项。
  • 自绘标题栏、弹窗、表单和状态色都必须响应主题。
  • 首次启动默认跟随系统。

软件更新

使用 Tauri updater plugin。更新入口放在设置页，也支持启动后静默检查。

  • 发布包生成 updater artifacts。
  • 更新包必须签名，公钥写入 tauri.conf.json。
  • 支持 “检查中、无更新、可更新、下载中、安装中、失败” 状态。
  • 安装更新前先执行关闭前恢复，确保 Codex 配置干净。

自绘窗口栏

不使用系统窗口栏，窗口采用无边框设计，由前端绘制标题栏和窗口控制按钮。

  • decorations: false。
  • 标题栏拖拽区域使用 data-tauri-drag-region。
  • 按钮调用 Tauri Window API：最小化、最大化、关闭。
  • 关闭按钮不直接销毁窗口，必须走恢复流程。
关闭前自动恢复

应用收到关闭请求时，如果当前处于已启用状态，必须先停止代理并恢复 Codex 配置，再关闭窗口。这样用户关闭软件后 Codex 仍能直接使用官方配置，避免 Codex 请求继续指向已停止的本地代理。

核心流程

首次启用

读取 Codex 状态，启动本地代理，备份并写入固定 model_provider = "codex-switch"，Codex 只看到一个 provider。

切换第三方

确认 Key 状态，更新 active provider。代理即时切换，必要时更新 Codex 顶层 model。

检查更新

请求更新端点，展示版本说明。用户确认安装前执行配置恢复，随后下载并安装。

关闭应用

拦截 close requested，禁用主界面操作，执行 restore，然后调用真正关闭。

关闭前恢复伪代码
onWindowCloseRequested(event):
  event.preventDefault()
  if state.enabled:
    showClosingOverlay("正在恢复 Codex 配置")
    stopProxy()
    restoreCodexConfig()
    state.enabled = false
  destroyWindow()

安全边界

  • 代理只监听 127.0.0.1。
  • 不记录 API Key、Cookie、Authorization。
  • 不记录请求体、提示词、工具参数和模型输出。
  • 转发到 upstream 前必须删除 Codex 登录凭据。
  • Provider API Key 只存系统凭据。
  • 远程导入配置只允许 HTTPS 且必须确认。
  • 停用、关闭、更新前均要恢复 Codex 配置。
